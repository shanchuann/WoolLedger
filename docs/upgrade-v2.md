# 2.0 升级范围与验收

目标：可识别的交易通知自动生成账目；信息缺失和疑似重复进入待确认。蓝羊羊通过受限工具完成对话记账、查账、修改、删除、预算与对账。

沿用原生 Java/View 与现有纸色主题，不重新设计已有页面。单人实现、独立只读审查；保留原有账单和偏好，不清库。不会主动调用付费模型；联网规划需用户开启并使用自己的 Key。

## 数据与状态

- 数据库 1→2 只新增 payment_event、agent_action、agent_message、ledger_setting，不删除账单。
- 通知默认关闭；用户明确开启后仅读取白名单应用的新通知。不回放历史通知，不上传通知原文。
- 事件：pending → posted / ignored；已入账支持撤销为 ignored，保留去重标记。重复通知不得再次入账。
- 明确成功、金额唯一、收支方向和商户齐全且无疑似重复才能自动入账。退款、转账、还款以及缺失字段仅待确认。
- Agent：规划 → 校验 → 持久化预览 → 确认 → 原子执行；每个动作最多执行一次。修改和撤销前比较快照，过期则拒绝。
- 查询与对账只读。金额来自本地数据库，不采用模型编造的统计数字。不执行模型提供的 SQL、文件或任意代码。

## 验收

1. 旧库升级后原账目逐字段不变，首次新库包含所有新表。
2. 通知识别覆盖支付/收入/缺失金额/多金额/余额/失败/营销/退款/转账；重复和更新幂等，跨来源相同金额待确认。
3. 待确认允许修正字段、确认、忽略；自动入账可以撤销。重启后状态保持。
4. Agent 多笔记账、查账、汇总、预算、按 ID 改删和撤销可用；没有确认不得写账，重复确认不得重复写入。
5. 构建、单元/设备测试、Lint 与独立审查记录实际结果。通知真实覆盖率以支付软件实际通知为准；合成样本不能替代真机验收。

不包含：读取支付软件私有数据库、无障碍抓屏、短信权限、支付操作、银行账户登录。平台账单文件格式适配后续独立扩展，现有 CSV 导入继续可用。

## 使用入口

- 首页「支付通知 · 待确认」或「我的 → 支付通知自动记账」进入设置和队列。
- 自动读取默认关闭；开启后需系统通知使用权。明确交易默认自动入账，可切换成全部确认。
- Agent 页右上角「待确认」进入通知队列。记录和改删可直接输入；变更先预览，再点击确认。已执行卡片可撤销。
- 本地规则无需 API Key。复杂多轮请求需要在「我的 → 联网理解请求」明确开启，并使用自行配置的服务；通知原文不发给模型。

- 19 个通知解析单元测试通过，包括明确支付/收入、余额排除、缺失字段、多金额、失败、营销、验证码、退款、转账和未完成交易。

- 设备测试包含数据库增量迁移、重复与更新通知、不同时间的重放、跨来源疑似重复、手动确认幂等、撤销冲突、清空隐私字段、Agent 多笔记账/改删/预算/撤销/查询/对账，以及卡片点击、浅深色页面打开和会话恢复。

- 独立只读审查指出的5项问题均已修复，并加入回归用例：未完成交易误入账、变更通知时间绕过去重、交易号候选无法补全、清空残留快照、本地意图把日期当金额。
- Lint：0 errors、307 warnings；原有录音/震动权限声明、字体常量与 AppCompat tint 错误已修复。Fragment1.5.4 的递归生命周期检测器曾持续递归8分钟，临时停用3项相关检查；当前代码无对应 LiveData/menu/back callback API 用法，其余检查运行完成。后续升级 Fragment 检测器时应恢复。
- Debug 包与本地原 `wool_ledger.apk` 的证书 SHA256 一致，可以作为该旧包的覆盖升级；Release 包使用本地正式密钥，与旧 Debug 安装的签名不同，应区分分发。

## 尚待真实环境验收

没有连接实体手机，未实际支付，也未调用付费联网模型。本轮不宣称各支付软件全覆盖，不宣称多轮模型效果已验收。需要在目标手机打开通知使用权后，分别核对支付、退款、转账、锁屏通知、重复通知和后台省电行为。通知缺失时需人工补记或使用现有 CSV 导入。

若需要退回1.54，应先导出账目。旧版不认识新版数据库，不能承诺直接安装旧APK即可无损降级；还原应使用升级前的完整应用备份。

覆盖升级验证：在只读模拟器安装原1.54 APK，创建15笔原始演示账目，再使用2.0.0 Debug APK覆盖安装。读取升级前后SQLite对比，schema 1→2，15笔账目所有字段与编号完全一致。
